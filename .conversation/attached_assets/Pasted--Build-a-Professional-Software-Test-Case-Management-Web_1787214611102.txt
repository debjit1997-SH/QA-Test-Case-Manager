# Build a Professional Software Test Case Management Web Application

Build a fully functional, production-quality **Software Test Case Management System** for managing software testing activities.

The application will be used by software testers and administrators to create, execute, review, edit, and manage software test cases module-wise.

Do NOT create a simple demo or mockup. Build a complete working web application with a real database, authentication, role-based access control, validations, persistent data, file/link attachments, and a professional responsive UI.

---

# 1. Technology Requirements

Use a modern and reliable full-stack architecture suitable for Replit.

Preferred stack:

* Frontend: React / Next.js
* Backend: Node.js / Next.js API routes
* Database: PostgreSQL
* ORM: Prisma or another reliable ORM
* Authentication: Secure session-based authentication or JWT with secure password hashing
* Password hashing: bcrypt/argon2
* File uploads: Use a reliable storage solution compatible with Replit
* UI: Tailwind CSS
* Icons: Lucide React or equivalent
* Charts are optional but the dashboard should be extensible.

Do NOT store important application data only in browser localStorage.

All users, test cases, modules, access requests, attachments, etc. must be stored persistently in the database.

# 11. TEST CASE NUMBER GENERATION — VERY IMPORTANT

This is a critical requirement.

Test case numbers must be automatically generated.

The test case number must be unique.

There must NEVER be duplicate test case numbers.

Test case numbers should be module-specific.

Example:

LOGIN:

* LOGIN-TC-001
* LOGIN-TC-002
* LOGIN-TC-003

GRN:

* GRN-TC-001
* GRN-TC-002
* GRN-TC-003

BILLING:

* BILLING-TC-001
* BILLING-TC-002

If a new test case is created under GRN, automatically determine the next available GRN number.

Example:

Existing:

GRN-TC-001
GRN-TC-002
GRN-TC-003

New test case:

GRN-TC-004

If GRN-TC-003 is deleted, the system MUST NOT reuse GRN-TC-003.

The next new GRN test case must continue with:

GRN-TC-004

The numbering system must be concurrency-safe.

If two users create test cases simultaneously, they MUST NOT receive the same test case number.

Implement this using a database-level unique constraint and a transaction/atomic sequence mechanism.

Do NOT generate numbers using frontend array length.

Do NOT use:

`existingTestCases.length + 1`

because that can create duplicate numbers.

Use a proper database-backed sequence/counter per module.

Example database concept:

Module:

GRN

Sequence:

4

Next generated number:

GRN-TC-004
