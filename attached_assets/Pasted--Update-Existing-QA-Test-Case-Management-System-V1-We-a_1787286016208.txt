# Update Existing QA Test Case Management System — V1

We already have a working V1 of the QA Test Case Management System.

DO NOT rebuild the application from scratch.

DO NOT remove or break any existing working functionality unless explicitly mentioned below.

First inspect the existing application, database schema, authentication, role permissions, test case creation flow, test case listing, attachments, and PDF functionality.

Then implement the following changes carefully and test the complete workflow.

Currently there may be multiple "New Test Case" / "Create New Test Case" buttons throughout the application.

Remove all unnecessary duplicate entry points.

There should be only ONE proper place to start creating a test case:

**Create Test Case**

Inside the Create Test Case page, provide the actual:

button/action.

* Dashboard

The only test-case creation workflow should be:

**Create Test Case → New Test Case → Test Case Form**

Do not change the existing sidebar/menu structure unless necessary.

# 5. "PASSED ON" DATE/TIME

Add a new field/column:

**Passed On**

This represents the exact date and time when the test case was actually marked as PASS.

IMPORTANT:

The Passed On timestamp must NOT be the original test case creation date.

Example:

Test Case created:

20 Aug 2026, 10:00 AM

Initially:

Status = NOT TESTED

Later, on:

21 Aug 2026, 03:42 PM

the tester opens the test case, changes status to:

PASS

and clicks:

**Save**

Then:

Passed On = 21 Aug 2026, 03:42 PM

The system must capture this timestamp automatically from the server/database time.

Do NOT rely on the user's computer clock.

---

## Passed On Logic

If status is:

PASS

then Passed On must contain the timestamp when the test case was changed/saved as PASS.

If status is:

NOT TESTED, FAIL, or BLOCKED:

Passed On should display:

**NA**

or

**Not Passed**

Use one consistent display format throughout the application.

Recommended:

**Not Passed**

If a test case was previously PASS and later changed to FAIL/BLOCKED, the current Passed On value should be handled consistently.

For the current-status view, if the current status is not PASS:

**Passed On = Not Passed**

If the test case becomes PASS again later, update Passed On to the new timestamp when it is saved as PASS.

# 6. TEST CASE PERFORMED BY

In the View Test Cases list, show:

**Test Case Performed By**

This must represent the user who actually submitted/created the test case.

Then:

Performed By = User A

User B must never be able to change the original "Performed By" value.

Even if Admin edits the test case later, the original Performed By must remain the original submitting user.

Do not overwrite this field when another user edits the test case.
