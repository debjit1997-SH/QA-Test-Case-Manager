# 5. PASSED ON DATE/TIME

Add:

**Passed On**

This is NOT the Test Case Date.

It represents the exact date and time when the test case was actually changed/saved as:

**PASS**

Example:

Test Case created:

20 Aug 2026, 10:00 AM

Initial status:

NOT TESTED

Later:

21 Aug 2026, 03:42 PM

User opens the test case, changes status to:

PASS

and clicks:

SAVE

Then:

Passed On:

21 Aug 2026, 03:42 PM

The timestamp must be automatically captured by the server/database.

Do NOT use the user's browser/device clock.

---

# 6. PASSED ON LOGIC

If current status is:

PASS

then:

Passed On = timestamp when the test case was saved as PASS.

If current status is:

NOT TESTED, FAIL, or BLOCKED:

Passed On =

**Not Passed**

If a previously passed test case is changed to FAIL or BLOCKED:

Current Status = FAIL/BLOCKED

Passed On = Not Passed

If it later becomes PASS again:

Update Passed On to the new server timestamp when it is saved as PASS.
